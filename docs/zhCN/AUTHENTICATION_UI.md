# 认证页面

登录页区分邮件或短信验证码、验证器动态码和备用码。更改账号、投递渠道或方式后，页面会丢弃当前 challenge 绑定；请为当前选择重新发码。后端的账号、用途及渠道校验保持有效。

登录请求进行时，账号与方式暂时锁定。页面不会自动重试请求。连接或响应异常时，操作可能已经完成，一次性验证码也可能已经消费；请先检查当前登录状态，再手动决定下一步。明确收到 HTTP 429 的重发会保留已知旧 challenge；结果不明的发送不会保留它。

倒计时只使用服务端提供的秒数。缺少合法等待信息时，仅显示一般限流提示。倒计时结束表示可以手动再次尝试，不保证一定投递成功，其他服务端限制仍可能生效。重新加载页面不会清除服务端计数。

绑定验证器成功后，请保存只显示一次的备用码列表。复制或下载仅由用户明确点击触发，不会写入 localStorage 或 sessionStorage；离开页面前，页面内存中仍有敏感信息。离开会清除页面中的设置密钥，浏览器后退不会恢复它们，也不会自动重新绑定。若确认结果不明或未保存的备用码丢失，请检查账号设置并联系管理员，不要反复重新开始绑定。

在认证域名打开 `/_account` 可管理当前会话，并使用同源 POST 退出按钮。退出只针对当前浏览器会话，不表示撤销所有设备。根路径原有的纯文本响应保持不变。

可通过 `LOGIN_SUPPORT_URL` 配置求助链接，详见[配置说明](CONFIG.md#login_support_url)。未配置时隐藏链接，不显示无效占位地址。
